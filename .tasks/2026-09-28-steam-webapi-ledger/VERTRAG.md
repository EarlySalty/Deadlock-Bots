# Steam Web API reservation contract

The service is bound to `127.0.0.1:8901` in `dl-bot`, outside the public Caddy routes. Both routes require `X-Internal-Token` with the existing ServerSync credential (`SERVERSYNC_INTERNAL_TOKEN`, falling back to `MASTER_BROKER_TOKEN`, `MAIN_BOT_INTERNAL_TOKEN`, `TWITCH_INTERNAL_API_TOKEN`). The key must come from the existing Infisical service environment, never from TOML or a request body. A missing service key returns 503; missing caller key returns 403; an invalid key returns 401. Non-loopback callers return 403. Other hosts need a controlled private forwarding path, not a public proxy route.

`POST http://127.0.0.1:8901/steam-web-api/reserve` with JSON `{"caller":"patchnotes","caller_class":"optional_patch"}`. `caller` is a lowercase identifier of at most 64 characters (`[a-z][a-z0-9_-]*`). `caller_class` is `optional_patch` for the repeated optional news check or `standard` for other Steam Web API work, including required localization after detection. Successful authorization returns HTTP 200 with one of:

- `{"ok":true,"granted":true,"reservation_id":123,"reserved_at":"2026-09-28T12:00:00Z"}`. Dispatch exactly one Steam Web API request for this ID. A failed request still consumes its reservation.
- `{"ok":true,"granted":false,"reason":"cooldown","retry_at":"2026-09-28T12:01:30Z"}`. Reasons are `cooldown`, `global_cap`, `optional_cap`. Do not dispatch. `retry_at` is the earliest possible next attempt, not a promise that capacity will remain available.

`POST http://127.0.0.1:8901/steam-web-api/observe` with JSON `{"reservation_id":123,"http_status":429,"retry_after":"90"}` immediately after the response. Pass the upstream `Retry-After` header verbatim if status is 429. For another HTTP response use its status and omit `retry_after`; for a transport failure send `"http_status":null`. The response is `{"ok":true,"response_at":"2026-09-28T12:00:01Z","cooldown_until":"2026-09-28T12:01:31Z","duplicate":false}`. A repeated identical observation returns `duplicate:true` without extending the cooldown; a conflicting report returns 409. `cooldown_until` may be null. The server parses numeric seconds or an HTTP date; a missing or invalid header uses persistent staged 30/60/120/300/900-second backoff. The cooldown and response time survive process restarts in central PostgreSQL.

Reservations serialize on one PostgreSQL row. They count every attempt within the preceding rolling 24 hours, including transport errors and 429s. The global limit is 100,000; `optional_patch` is limited to 90,000. No reservation means no dispatch. The caller must fail closed on timeout, non-200, malformed JSON, or failed observation; retry the observation with the same reservation ID before resuming polling. PostgreSQL or the internal API being unavailable must not trigger direct Steam polling. Concurrent requests still receive distinct reservations or a denial.

The ledger cannot provide a system-wide 100,000-request guarantee until the productive Steam Web API calls in Patchnotes, Brain, Twitch Bot, Steam Bot, and any further consumers are inventoried and routed through this contract. This package does not switch those callers or deploy the service.
