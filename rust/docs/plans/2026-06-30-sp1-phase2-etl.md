# SP1 Phase 2 — ETL (Snapshot → zentrale Postgres) Implementation Plan

> **For agentic workers:** Dies ist ein Orchestrierungs-Plan. Umsetzung erfolgt durch Codex (gpt-5.5/xhigh): Codex implementiert **und** verifiziert sich selbst **und** reviewt sich selbst (frischer Kritiker). Claude orchestriert nur (DAG, commit/push, changed_files-Plausi) und schreibt user-sichtbare Texte. Siehe „Arbeitsmethode".

**Goal:** Eine ledger-getriebene, idempotente ETL-Engine, die jede gemappte Quellspalte aller drei Quell-DBs typkorrekt aus einem konsistenten Snapshot in die zentralen Postgres-Tabellen lädt — beweisbar ohne Datenverlust (Row-Count-Reconciliation + Round-Trip-Sampling gegen echte Daten).

**Architecture:** Generische Engine (eine Engine für alle 178 Tabellen, getrieben vom TOML-Ledger + Live-Ziel-Schema), keine 178 handgeschriebenen Loader. Pro gemappter Spalte wird der Konverter aus dem Paar `(SQLite-Affinität, Ziel-PG-Typ)` abgeleitet. Load = Upsert auf den Ziel-PK (idempotent, union-fähig, parallel-sicher). Verifikation über die bestehenden `verify::*`-Gates, erweitert um Total-Reconciliation.

**Tech Stack:** Rust, rusqlite (read-only Quelle), sqlx/Postgres (Ziel), bestehende Crate `dl-central-etl` (convert/ledger/source/target/verify), Wegwerf-DB-Harness `rust/scripts/central_test_db.sh`.

## Global Constraints

- **Null Datenverlust:** Jede `mapped`-Quellspalte landet typkorrekt im Ziel; jede `dropped`-Spalte ist und bleibt gelistet. Kein stilles Verschlucken — ein nicht-konvertierbarer Wert ist ein **harter Fehler**, keine stille Null/Default.
- **Snapshot-only:** ETL liest NIE die Live-Quell-DBs direkt. Zuerst konsistenter Snapshot (SQLite Backup-API bzw. `VACUUM INTO`), ETL läuft gegen die Kopie. Original-Snapshot ist sakrosankt (Leitplanke #6), wird nie verändert/gelöscht.
- **Idempotent:** Zweimal laufen ⇒ identischer Ziel-Zustand. Load = `INSERT … ON CONFLICT (<pk>) DO UPDATE SET <alle nicht-pk-Spalten> = EXCLUDED.…` (Overwrite, damit Ziel == Quelle exakt).
- **#387-Unions:** `coaching.requests`/`coaches`/`coach_applications` (deadlock-sqlite3 + website) und `core.steam_links` (deadlock-sqlite3 + steam) erhalten Inserts aus BEIDEN Quellen auf disjunkte PKs; Reconciliation = Summe über Quellen.
- **TEXT→BIGINT validiert:** Jeder TEXT→BIGINT-Cast (Discord-/Snowflake-IDs, z. B. `user_data.user_id`, `meta_users.id`) prüft Numerik + int8-Range; nicht passende Werte = harter Fehler mit Quell-PK im Report.
- **Schema unverändert:** Migrationen 0001–0011 sind eingefroren. Phase 2 ändert KEINE Migration und KEIN Ledger-Mapping. Wird ein echter Schema-/Ledger-Fehler entdeckt, STOP + an Claude melden (Rücksprache-Aktionsklasse), nicht eigenmächtig Schema biegen.
- **Kein git** durch Worker. **WORKFLOW.md** niemals anfassen. Keine Consumer-Query-Rewrites (das ist Phase 3). Keine user-sichtbaren Produktstrings (nur `"Platzhalter"` + Datei:Zeile melden).
- **Secrets** nur via Infisical-Loader; nie `.env`/`service_token`/`/proc/environ`; nie Secret-Komponenten ausgeben.
- Verifikation gegen Wegwerf-DB (`central_test_db.sh`), nie gegen die Prod-Instanz `:5434`.

## Datei-Struktur (Ownership, kollisionsfrei)

- `src/snapshot.rs` (CREATE, T0): konsistenter Read-only-Snapshot der 3 Quell-DBs in ein Arbeitsverzeichnis.
- `src/convert.rs` (MODIFY, T0): `text_to_bigint` (+ optional) validiert ergänzen.
- `src/plan.rs` (CREATE, T0): aus Ledger + Live-Ziel-Schema die Spalten-Konvertierungs-Matrix `(source_affinity, target_pg_type) → Converter` ableiten; Ziel-PK pro Tabelle aus `information_schema` lesen.
- `src/target.rs` (MODIFY, T0): echtes typisiertes Upsert pro Tabelle (PK-Konflikt → Overwrite), batched.
- `src/engine.rs` (CREATE, T0): `migrate_table(source, target, mapping)` + `run(ledger_set, snapshot, pool)`; orchestriert Extract→Transform→Load + ruft Gates.
- `src/verify.rs` (MODIFY, T0/T4): `reconcile_total` (Summe Quellzeilen je Ziel == Ziel-Zeilen, union-aware) ergänzen.
- `tests/etl_engine.rs` (CREATE, T0): Tracer + Zähne (nicht-konvertierbar → Err).
- `tests/etl_<sourcedb>.rs` (CREATE, T1–T3): je Quell-DB Row-Count + Round-Trip pro Tabelle gegen Mini-Snapshot-Fixtures.
- `tests/etl_barrier.rs` (CREATE, T4): Total-Reconciliation + Idempotenz-Doppellauf + Union.

## Task T0: Foundation — Engine, Snapshot, Konverter-Matrix, Tracer

**Files:** Create `src/snapshot.rs`, `src/plan.rs`, `src/engine.rs`, `tests/etl_engine.rs`; Modify `src/convert.rs`, `src/target.rs`, `src/verify.rs`, `src/lib.rs`.

**Interfaces — Produces (spätere Tasks verlassen sich darauf):**
- `engine::run(ledger_set: &LedgerSet, snapshot_dir: &Path, pool: &PgPool) -> Result<EtlReport, EngineError>` — lädt alle Tabellen aller Sources; idempotent.
- `engine::migrate_table(...)` pro (source_db, table) → EXTRACT (read_rows) → TRANSFORM (plan-Matrix-Konverter) → LOAD (target upsert).
- `plan::conversion_for(source_affinity, target_pg_type) -> Converter` — deterministische Matrix; unbekanntes Paar = harter Fehler (nicht still durchreichen).
- `convert::text_to_bigint(&str) -> Result<i64, ConvertError>` + `optional_text_to_bigint`.
- `verify::reconcile_total(...)` — Quell-Zeilensumme je Ziel == Ziel-Zeilen (union-aware), sonst Err mit Tabelle + Differenz.
- `EtlReport { tables: Vec<TableResult{ target, source_rows, loaded_rows, dropped_cols }>, total_source_rows, total_loaded }`.

**DoD:**
- Konverter-Matrix deckt mind.: SQLite INTEGER→`timestamptz` (unix), INTEGER→`boolean` (0/1), TEXT→`jsonb`, TEXT→`bigint` (validiert), und alle 1:1-Fälle (TEXT→text, INTEGER→int8/int4, REAL→float8). Unbekanntes Paar ⇒ `EngineError::NoConverter{source_affinity, target_type, table, column}`.
- Snapshot erzeugt read-only Kopien der 3 Quell-DBs; ETL öffnet nur die Kopie; Original unangetastet (mtime/hash-Beleg).
- **Tracer Bullet:** je eine Tabelle pro „Form" end-to-end gegen Wegwerf-DB grün: (a) unix/bool-Tabelle (z. B. `voice`-Tabelle), (b) jsonb-Tabelle, (c) TEXT→BIGINT-Tabelle (`core.user_data`), (d) eine Union-Tabelle (eine Quelle). Für jede: row-count == Quelle, round-trip Stichprobe gleich.
- **Zähne:** (1) nicht-numerischer TEXT in TEXT→BIGINT-Spalte ⇒ Err mit Quell-PK; (2) unbekanntes Typ-Paar ⇒ `NoConverter`; (3) zweiter Lauf ⇒ identischer Ziel-Zustand (Idempotenz).
- `cargo test -p dl-central-etl` voll grün; `central_test_db.sh`-gestützte Tests (`-- --ignored`) grün; clippy `-D warnings` (zentrale Crates) grün.
- Frischer Kritiker FREIGABE (Fokus: Matrix vollständig & nicht still-durchreichend, TEXT→BIGINT wirklich validiert, Snapshot wirklich read-only, Idempotenz echt).

## Tasks T1–T3: Load je Quell-DB (parallel nach T0)

- **T1 deadlock-sqlite3** (124 Tab.): Engine über alle deadlock-sqlite3-Mappings; seine Hälfte der Unions (coaching/steam_links). Pro Tabelle Row-Count + Round-Trip-Stichprobe gegen Mini-Fixture-Snapshot. Quirks (TEXT→BIGINT-Spalten, json-Spalten, 0/1-bool) explizit getestet.
- **T2 website** (21 Tab.): analog; website-Hälfte der coaching-Unions (request_uid disjunkt zur bot-Hälfte).
- **T3 tournament** (38 Tab.): analog; reine 1:1-Loads, sqlx-sqlite-Herkunft beachten.

**DoD je T1–T3:** Für JEDE Tabelle der Quelle: `source_rows == loaded_rows` (bzw. union-Beitrag korrekt), Round-Trip-Stichprobe (≥3 Zeilen/Tabelle, alle gemappten Spalten typkorrekt). `cargo test -p dl-central-etl --lib` + eigener Test grün. Kein `--lib`-fremder Volltest-Bruch durch fremde Slices (Barrier macht Volltest grün). Frischer Kritiker je Slice oder gebündelt vor Barrier.

## Task T4: Barrier — Total-Reconciliation, Union, Idempotenz

**Files:** Create `tests/etl_barrier.rs`; ggf. Modify `src/engine.rs`/`src/verify.rs` (nur Reconciliation, keine Slice-Logik).

**DoD:**
- Voller `engine::run` über echte Snapshots aller 3 Quell-DBs gegen frische Wegwerf-DB.
- **Total-No-Loss-Report:** Σ Quellzeilen über alle Tabellen == Σ geladene Zeilen + explizit erfasste Drops (keine Tabelle, keine Zeile unerklärt). Union-Ziele = Summe beider Quell-Hälften, beide round-trip-belegt.
- **Idempotenz:** zweiter voller `run` ⇒ identische Ziel-Zeilenzahlen + Stichprobe unverändert.
- Voller `cargo test -p dl-central-etl` grün (kein MissingSource-Reststand); drift-frei (`central_fresh_schema.sh`); clippy `-D warnings` grün.
- **Zähne (Barrier-Ebene):** in einem Mini-Snapshot eine Quellzeile künstlich „verlieren" (Loader-Stub) ⇒ `reconcile_total` FAIL mit Tabelle+Differenz ⇒ revert grün.
- Frischer Kritiker FREIGABE über das Ganze (Fokus: Reconciliation nicht trivial-grün, Unions beidseitig, Idempotenz echt, kein still-übersprungenes Ziel).
